# Обновление до 10.6.0

Версия 10.6.0 включает исправления 10.5.0 и бесплатный генератор версии 8. Собственный словарь и новая обработка описаний описаны в [CONTENT-FREE.md](CONTENT-FREE.md). Для этих функций не требуется AI API или доработка сервера. Старые черновики следует обновить; утверждённые и ручные описания сохраняются.

Сборка подготовлена на основе присланного приложения 10.4.0. На хостинге 6 октября обнаружена версия 10.1.3. Проверено чтение и запуск существующих миграций с резервной копией 10.1.3: все 3 113 товаров и 8 734 RUB-SKU сохранены.

## Установка

1. Скачайте свежую резервную копию из действующей PIM и сохраните старые файлы приложения.
2. Сначала откройте новую сборку на тестовом адресе и импортируйте копию. При переходе с другого адреса база браузера сама не переносится.
3. Разместите основной HTML и папки `lib/`, `vendor/` рядом. В ZIP `index.html` и `rubizh_pim.html` содержат одну и ту же сборку. Если хостинг открывает `index.html`, используйте его. Замена одного HTML без `lib/` недостаточна.
4. Проверьте каталог и условия каждого поставщика. Обновите прайсы. В копии пользователя данные о наличии датированы 3–4 октября; подтверждённых правил изготовления нет.
5. В «Контент для сайта» создайте черновики, посмотрите предупреждения и примените подходящие описания общей кнопкой. Ручные описания защищены. Противоречивые и непереведённые данные блокируют применение.
6. В «Комплекти» выполните подбор, исправьте отмеченные проблемы и утвердите состав. Передачу на сайт выполняет отдельная публикация.

Настройка показа недоступных товаров по запросу владельца включена: они остаются в каталоге со своим настоящим статусом. Предзаказ появляется только по данным прайса или подтверждённым условиям поставщика. Срок «3 дня» не подставляется вместо неизвестного срока.

## Подтверждённый предзаказ

Для поставщика, который действительно изготавливает ассортимент, укажите предзаказ, подтвердите это решение и заполните срок, например `3` или `2-3 робочі дні`. Политика относится ко всему ассортименту поставщика; исключения отмечаются вручную у предложения товара. Не задавайте эту политику поставщику, который только перепродаёт остатки.

В конструкторе комплектов можно разрешить подтверждённое изготовление или использовать только наличие. По умолчанию новые черновики допускают подтверждённое изготовление до трёх дней. Позиции предзаказа имеют отдельное предупреждение, а срок комплекта — максимальный срок его позиций. Рабочие дни нужно отображать как рабочие дни и учитывать календарь на сервере магазина; выходные нельзя выдавать за дни производства.

## Сервер магазина

Серверная часть в предоставленных файлах отсутствует. Для новых комплектов требуется контракт v1 из `server-contract.md`: количество единиц, разрешённые RUB-SKU, общие размеры/рост, актуальная цена, наличие/изготовление и атомарное резервирование заказа. Если сервер не подтверждает поддержку и сохранение состава, PIM показывает ошибку и не отмечает передачу завершённой.

Публикация товаров без утверждённых комплектов продолжает использовать существующий API. После утверждения комплектов сервер должен поддерживать новый контракт до следующей публикации. ZIP не обновляет PHP/MySQL или оформление заказа самостоятельно.

## Локальный запуск

```sh
cd app
npm ci --ignore-scripts
npm test
npm run serve
```

Откройте `/rubizh_pim.html` на порту 8765. Node нужен для проверок, Python — для локального HTTP. В production приложение остаётся статическим HTML/JS. `npm run build` собирает изменения из `lib/*.inc.js` в основной HTML.

Исходные проверки `tests/test.cjs` сохранены как `npm run test:legacy`. Для них нужен отдельный исторический исправленный каталог, отсутствующий в исходном архиве; текущие автоматические проверки самодостаточны.

Ключ магазина сохраняется локально. Обмен настройками между устройствами удаляет секреты и выключает автоматическую публикацию на другом устройстве. Если ключ нужно добавить на новом устройстве, введите его в настройках публикации. Старые записи на сервере с ключами потребуют отдельной проверки и очистки администратором сервера.
