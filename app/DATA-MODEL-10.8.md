# PIM 10.8.0 — модель данных и контроль качества

Обновление бесплатное: локальные правила, словари и проверки; платных AI API не требуется.

## Включение

1. Сделайте полный JSON export в текущем браузере PIM.
2. Если категории ещё не мигрированы: «Категоризація» → dry run → применить проверенные категории.
3. Откройте «Инструменты и настройки» → «Якість і дані» → PREVIEW.
4. Посмотрите оценку заполненности, причины BLOCKED и первые 20 примеров; полный JSON отчёт содержит все позиции.
5. APPLY создаёт резервную копию до изменения, сохраняет новые поля и независимо сверяет запись. «Відкотити нормалізацію» возвращает полную копию: позднейшие изменения также откатываются, поэтому перед откатом создаётся новая копия.

PREVIEW и APPLY больших каталогов показывают прогресс каждые 100 товаров. Новые строгие проверки публикации активируются после APPLY. Ранее сохранённые исходники, значения цен, остатков, фото и SKU сохраняются.

## Карточка

Нижний блок «Дані для сайту» содержит отдельное marketing_name_uk, primary_product_type, компонент комплекта, участие в автоподборе, приоритет 0–100, уровень basic/optimal/premium и группу аналогов. Ручные данные защищены при повторном импорте. Изменения записываются с автором, временем, значением до/после и причиной.

«Сумісний з» / «Не сумісний з» принимают ID карточек через запятую. Ссылки на себя, отсутствующие товары и противоречия блокируются. Ручная несовместимость имеет приоритет. Технические спецификации редактируются отдельно как JSON; отсутствующие параметры и размеры плит без единиц не доказывают совместимость. recommended_with и типизированные relations хранят рекомендации, аналоги, замену и bundle отдельно от вариантов.

Структурированные ручные attributes редактируются как JSON. Неизвестные значения сохраняются для уточнения. «Піксель» и ММ14 — разные паттерны; неопознанный паттерн не заменяется ближайшим знакомым. Цвет и камуфляж имеют отдельные поля. Для универсального размера одежды есть отдельное подтверждение производителя; пустой размер не превращается в «Один розмір».

## Качество и публикация

quality_score — заполненность десяти критериев, а не точность классификатора. READY / READY_WITH_WARNINGS / BLOCKED определяются отдельно: хороший балл не снимает критическую ошибку. Для совместимости критерий обязателен только для типов с техническими сопряжениями, например плиты/плитоноски, рации/PTT, шлемы/гарнитуры.

Строгая публикация блокирует карточки без категории, цены, фото, доступного варианта, с неподтверждёнными обязательными размерами или критической группировкой. Маржа ниже 20% требует обоснованного разрешённого исключения. Значения старых цен автоматически не повышаются: существующие правила дорогих товаров ниже 20% выявляются проверкой. Предзаказ возможен только с явным подтверждением. Нулевой остаток и устаревшая информация не доказывают возможность изготовления.

Истёкший срок данных поставщика исправляется обновлением его прайса. Отсутствие наличия само по себе не создаёт отдельное ручное задание на каждый товар. В копии от 5 октября все сведения о наличии устарели к 8 октября; это не доказательство фактического отсутствия товара у поставщика сегодня.

## Импорт

До предпросмотра создаётся полный внутренний backup. IMPORT/APPLY сохраняет просмотренные изменения; CANCEL возвращает снимок. Дополнительно показываются изменения цен, наличия и категории. Цена с аномальным скачком требует решения; порог берётся из действующих настроек.

Группировка использует поставщика, конкретную модель либо фото с названием/брендом, контекст изделия и SKU. Одного названия недостаточно. При неизвестной идентичности отдельные SKU остаются отдельными карточками или в очереди. Новый вариант надёжно найденной модели добавляется к существующей карточке. По умолчанию более 50 вариантов блокируют создание карточки/расширение; данные остаются в очереди. Лимит настраивается отдельно по canonical ID.

Вручную архивированный товар не восстанавливается из-за импорта. Автоматический архив отсутствующих предложений может восстановиться после их возвращения. Фото хранятся ссылками, общие изображения физически не размножаются.

## Таксономия сайта

В настройках category_metadata задаётся по canonical ID: filters, banner_asset, banner_active, banner_version. Базовые структурированные схемы фильтров формируются по типу категории. Legacy поля сохраняются рядом с authoritative fields.

Сервер магазина должен объявить product_model_version>=1 в /pim/status и подтверждать сохранение новой модели в results каждого товара. Пока этого нет, PIM прекращает POST и показывает причину. Сервер магазина отсутствует в переданных исходниках; его запись в БД, витрина, резервирование заказа и реальная синхронизация не проверены и не изменены. Подробнее: server-contract.md.
