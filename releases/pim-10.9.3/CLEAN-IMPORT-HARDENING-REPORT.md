**Почему READY 1698 → 1476 (только M-WIN, 306 → 89; остальные поставщики без изменений).** Раньше каждая
размерная строка сетки M-WIN была отдельной публичной карточкой (до 48 карточек на одну сетку). Теперь размер
сетки — точный размер SKU, и строки одной группы поставщика стали одной моделью (25 групп сеток объединены,
ARCHIVED 110 → 760 — поглощённые карточки). Модели разных цветов одной сетки у поставщика — **разные группы**,
поэтому объединение цветов в одну MODEL — решение владельца (МОДЕРАЦИЯ, одна кнопка на группу); до него
одноцветные модели ждут в модерации, а не публикуются дублями. Это осознанный выбор: правильная модель важнее числа READY.

## Решения владельца, реализованные в коде

1. **Сетки M-WIN (W×H).** Правило `m-win-net-grid-v1`: поставщик M-WIN + каноническая категория `camouflage_nets`
   + путь поставщика «Маскувальні сітки» + название «…сітк…» + значение `W×H` (1…50 м); название и Ширина/Довжина
   не должны противоречить. Значение — точный размер **существующего** SKU поставщика («3×4 м»). «Індивідуальний
   розмір» — не размер: `price_unit`, MODERATION, оплата запрещена. Вне сеток селектор игнорируется.
2. **Tactical Belt — STATUS.** `@available` true → IN_STOCK, false → OUT_OF_STOCK; нет/неизвестно → UNKNOWN;
   `quantity_in_stock` только проверяет: «есть» с 0 или «нет» с >0 → UNKNOWN. Точное количество хранится приватно и
   не публикуется.
3. **Диапазоны 42–60 / 44–54 / 46–58 / 48–60** — допустимые размеры модели (шаг 2; обувь шаг 1), `sku=null`,
   SIZE_CONFIRMATION_REQUIRED, оплата запрещена; диапазон создаёт 0 SKU (регрессионные тесты).
4. **Одна функция различимости** (`variantCellKey`: публичный цвет + публичный размер) — для проверки группировки,
   variant_cell и показа метки поставщика.
5. **READY без единого пригодного варианта невозможен**: ни у одного SKU нет цены → REJECTED NO_PRICE; плохой SKU
   внутри READY-модели публикуется отключённым (цена null, оплата и заявка запрещены). RUB-18620 (цена поставщика 0)
   — именно такой случай.
6. **MODEL → COLOR после классификации** при импорте: размеры, доказанные только классификацией (сетки), объединяют
   строки в том же импорте. Один код группы поставщика с одинаковым названием (без собственного размера) — модель
   этого цвета; карточки «за м²» в неё не входят; цвет поставщика дописывается в название, если его там нет.

## Что исправлено

1. **Размер из SKU-полей.** Для категорий, где размер необязателен, точный размер из структурного поля оффера
   (SAFE_AUTO EXACT/ONE) больше не теряется → SIZE_CONFIRMATION_REQUIRED 1215 → 1112.
2. **Диапазоны размеров** (уточнение владельца): `42–60` — допустимый диапазон МОДЕЛИ, clothing_numeric шаг 2,
   опции `sku=null`, SIZE_CONFIRMATION_REQUIRED, оплата запрещена, нужна подтверждение заказа. Никогда
   `size_normalized="42-60"`, никаких SKU из диапазона; обувь — шаг 1. Регрессии: 42–60, 44–54, 46-58, 48–60.
3. **Неразличимые SKU** (одинаковые публичные цвет+размер) и **цена за м²** — никогда не READY (новые причины
   `variant_cell`, `price_unit`), вместо тихой публикации неверной цены или двух одинаковых кнопок.
4. **Группы поставщика как срезы цвета/размера** (Киборг, Армолайн): разные коды не считаются конфликтом, когда
   каждая карточка — один цвет или один размер; автоматические подгруппы по идентичности без собственного размера.
5. **Собственный размер в названии** («… Розмір 50», кириллические М/Х) не мешает идентичности модели.
6. **Описание оффера** — evidence для категории/размера, если у карточки описания нет.
7. **Категория 843 → 520:** 21 проверенное supplier-scoped соответствие пути (`approved-evidence-rules.json`,
   `supplierMappings`, confidence 0.95, guard `name_must_not_contradict`); подтверждённые соответствия
   применяются к свежим карточкам (`category_source = mapping`), ручные блокировки не трогаются.
8. **Цвета 95 → 72:** словари (Ranger Green «рейнджер грін», «темний-хакі», «альпійська клякса»).
9. **Галереи цветов:** фото, привязанные к SKU, имеют приоритет над общей галереей карточки — общих фото между
   цветами 1566 → 79.
10. **Контент:** дубли описаний убираются при импорте и публикации; шумовые сегменты поставщика («|…») в
    названиях режутся только с проверкой префикса; две READY-карточки с одинаковым названием → модерация;
    slug из публичного названия; характеристики RU→UA; размеры в логическом порядке (XXS…6XL, числовые);
    типографский апостроф ’.
