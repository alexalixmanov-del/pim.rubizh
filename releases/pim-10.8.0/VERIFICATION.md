# PIM 10.8.0 — нормализованные данные и безопасная автоматизация

Бесплатное обновление клиентской PIM по новому ТЗ. Исходники поставщика отделены от нормализованных данных; добавлены marketing name, тип изделия, структурированные характеристики, размерные системы, отдельные цвет и камуфляж, оценка заполненности и готовность к публикации.

Ручные категории, характеристики, совместимость и рекомендации защищены от повторного импорта. Конструктор учитывает ручную несовместимость, участие товара, приоритет и бюджетный уровень. Подбор не считает неизвестные размеры/соединения доказанной совместимостью.

Импорт сохраняет исходные строки и историю новых изменений цен. Одно название больше не доказывает принадлежность вариантов одной модели; превышение настроенного лимита оставляет строки в очереди. Есть предпросмотр массовых операций, полная копия до записи и откат нормализации.

## Проверено

- 404 автоматических теста: 404 passed, 0 failed, 0 skipped.
- Chromium: реальные PREVIEW/APPLY, ручное сохранение, повторная загрузка, новые связи, CANCEL/APPLY массовой операции и откат. 9 экранов × 3 ширины × 2 темы = 54 раскладки, без ошибок JavaScript и горизонтального переполнения.
- Повторные импорты пяти поставщиков: свежий импорт, повтор, цена, остаток, название, категория, фото, добавленный и исчезнувший вариант. Файлы восстановлены из копии каталога; оригинальные прайсы ещё не проверены.
- Синтетический каталог 10000 товаров: проверена обработка и повторное использование расчётов. Это не измерение точности на 10000 реальных товаров и не benchmark production.
- Статическая проверка: без замечаний. Повторная сборка даёт тот же runtime.

## Границы этой версии

Сервер магазина в переданных исходниках отсутствует. PIM формирует новый payload, но его сохранение, права менеджеров, фильтры витрины и резервирование заказа должны быть реализованы и проверены на backend. После включения новой модели PIM требует подтверждения её поддержки от API и показывает ошибку вместо ложного успеха. Полная production-приёмка по пункту 62 не объявляется завершённой.

Установка файлов и миграция данных — разные действия. После обновления: Ctrl+F5 → Якість і дані → PREVIEW → APPLY. Перед этим сохраните полный JSON export. Применение выполняется с внутренней полной копией и проверкой сохранения. Обновление файлов само по себе каталог не преобразует.

На хостинг из облачной среды изменения не отправлялись. [Команда для терминала adm.tools](TERMINAL.md) скачивает проверенный архив, сохраняет старые файлы вне webroot и выводит команду отката.

## Результаты итоговой проверки

404 автоматических теста: 404 pass, 0 fail, 0 skipped. Chromium проверил PREVIEW/APPLY, ручную карточку, reload, защиту приватной закупочной цены в payload, массовые CANCEL/APPLY и откат; 54 раскладки (9 экранов × 3 ширины × 2 темы) без JS-ошибок и переполнения. Статическая проверка без замечаний.

На загруженной копии проверены 3113 товаров, 8734 варианта и 19132 фото. После применения и независимого чтения сохранённых данных цены, остатки, исходные варианты, SKU, имена, фото и pub-флаги совпадают с состоянием до нормализации. Персональный каталог в архив и Git не включён.

По новой расширенной проверке данных: 69 конфликтов категорий; 333 карточки без подтверждённого canonical ID; 387 карточек без подтверждённого обязательного размера; 199 карточек, у которых варианты не проходят новый guard маржи; 1 карточка выше порога количества вариантов; 4 без фото; 7 требуют завершения перевода. Причины могут пересекаться. 1463 карточки имеют проблемы данных по общему review-фильтру, включая неизвестные значения словарей. Это не 1463 конфликта категорий: общие aliases исправляются правилом для группы, а не ручным изменением каждой карточки.

Все 3113 карточек копии имеют BLOCKED по доступности, потому что сведения о наличии датированы 5 октября и устарели по настройке freshHours=36 к моменту проверки 8 октября. Это не утверждение, что у поставщиков реально нет товара сегодня. Обновление прайса решает свежесть сразу для поставщика и не создаёт отдельную ручную задачу на каждый товар.

Локальные реконструированные импорты пяти поставщиков прошли матрицу повторяемости; оригинальные файлы не проверены. Синтетический прогон 10000 карточек: первый расчёт 7130 мс, повторное чтение округлено до 0 мс, после одной правки 628 мс. Это измерения в текущем окружении, а не production benchmark или оценка точности. Нормализация реальной копии в изолированной базе: preview 39264 мс, apply с backup/проверкой 184872 мс.

Установщик: 13 локальных проверок архива, сохранения серверных/посторонних файлов, прав доступа, ручного отката и автоматического отката при искусственном сбое. Фактический хостинг не изменялся.
