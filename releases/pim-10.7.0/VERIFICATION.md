# Категоризация PIM 10.7.0 — итоговая проверка

Дата: 8 октября 2026, Europe/Kiev. Все проверки выполнены на изолированной копии. Изменений на production-хостинге не выполнялось.

## 1–2. Канонические категории и ID

Ровно 134 согласованных ID: 18 корневых разделов и 116 конечных категорий. Список с названиями, родителями и aliases: [canonical-categories.json](canonical-categories.json). На сайте связь строится по ID; изменения названий не меняют ID.

## 3. Полное old → new mapping

В [old-category-mapping.json](old-category-mapping.json) есть запись для каждого из 342 прежних путей. Достоверно сопоставлено 235 путей; остальные явно отмечены как review/conflict, с NULL вместо выдуманного ID. Это не разрешение автоматически переносить все товары одной старой группы: учитываются источники и конкретный тип товара. Старые пути не удаляются из backup.

## 4. Supplier category mappings

Исходная база не содержала подтверждённых mappings нового формата. Автоматически они не создаются. Подтверждённые решения хранятся в `cfg.supplier_category_mapping`; сначала ограничиваются поставщиком, а при повторяющемся листе — полным исходным путём. Mapping можно добавить в план dry run или сохранить после миграции.

## 5. Alias dictionary

Aliases каждой категории включены в канонический JSON. RU/UA-эквиваленты, обработка апострофов, тире, пробелов, отдельных транслитераций и ошибок написания — в [classifier-core.js](classifier-core.js). Материал, пол, сезон и камуфляж не становятся категориями.

## 6. Автоматические правила

Ручное назначение → подтверждённый supplier mapping → mapping пути → правила группы поставщика с проверкой контекста → название → предложение из описания → тип из характеристик → review. Автопринятие от 0.95; подтверждённый mapping от 0.80; слабое совпадение остаётся предложением. Confidence — оценка правила, не калиброванная вероятность. Сохранённая последняя категория защищена при неопределённом новом источнике.

## 7. Отрицательные правила

Кавер/чехол/сумка/подсумок не являются объектом назначения; оружейный магазин требует контекста; обычная плита не является бронеплитой; флис как подкладка не меняет тип одежды; пустая аптечка не становится полным IFAK; тренировочный турникет не становится медицинским средством для применения; второстепенные компоненты не меняют основной тип. Общая совместимая группа уточняется названием, прямое противоречие остаётся конфликтом. Отдельно сохранены ограничения комплектов, включая рюкзаки для дронов и пользовательские ограничения ролей.

## 10. Не распознанные товары

260 позиций сохранены в NEEDS_REVIEW. Полный список с ID, названиями и исходными категориями находится в приватном JSON отчёта владельца и выгружается из PIM кнопкой «Завантажити звіт JSON». Пользовательский каталог не включается в публичный GitHub/архив. Не следует подменять отсутствующее подтверждение случайным правилом.

## 11. Conflicts

260 позиций сохранены в CONFLICT_REVIEW. Отчёт владельца содержит все ID, оба источника/причины и варианты решения. В PIM можно назначить категорию вручную или подтвердить supplier mapping. Пример обязательного конфликта: группа «Рюкзаки» и название «Підсумок для аптечки».

## 12. Ручные назначения

В переданном исходном backup распознано 0 назначений нового/старого ручного формата. Испытания специально создают ручные решения в карточках и очереди: повторный импорт и bulk mapping их сохраняют. История содержит ID, старую/новую категорию, источник, правило, время и пользователя.

## 13. Новые категории поставщиков

257 исходных групп ещё не имеют подтверждённого mapping. Это список источников для обучения, а не 257 новых публичных категорий. Полный список включён в отчёт владельца; предложения не превращаются в постоянные правила без подтверждения.

На каждом проходе — 24 существующих карточки; второй проход не создаёт дублей, не меняет цены, остатки и ID категорий, сохраняет ручное назначение. ## 15. Контроль сохранности

```text
LOST PRODUCTS = 0
LOST VARIANTS = 0
UNEXPECTED DUPLICATES = 0
PRICE CHANGES CAUSED BY MIGRATION = 0
STOCK CHANGES CAUSED BY MIGRATION = 0
```

Исходный полный снимок сохранён отдельно. Внутри PIM проверены автоматический backup, отсутствие изменения до dry run, блокировка устаревшего плана, откат при ошибке, сравнение защищённых полей и независимое чтение уже записанной базы. Старая категория сохранена как ценовая область; перенос каталога не изменяет ранее заданную наценку или правила минимальной маржи.

Проверки приложения: **242 тестов, 0 ошибок/пропусков**; 25 разделов × 3 ширины = 75 проверок отображения без ошибок JavaScript и переполнения страницы. Браузер проверил staged review, bulk mapping, реальную запись, reload, кнопки карточки, XML-путь и ID предложения. Проверка кодовой сборки не нашла неизвестных переменных.

Сервер магазина не предоставлен. PIM отправляет canonical_category_id только после подтверждённой миграции и объявленной поддержки API v1. Без неё POST блокируется; без точного подтверждения ID успешный хэш не сохраняется. Требуемый [server-contract.md](server-contract.md) подготовлен, серверная реализация не заявляется выполненной.

На хостинге нужно установить файлы, затем отдельно выполнить dry run/миграцию. Этот отчёт не утверждает, что production уже обновлён. Платные AI-API не нужны.

Проверка установки: 13 успешных проверок, включая добавление модуля категорий, сохранение API/посторонних файлов и ручной/автоматический откат. SHA-256 конечного архива — в [manifest.json](manifest.json).

После публикации проверены реальные URLs GitHub: точный установщик, SHA-256 архива, установка runtime и откат в отдельной папке — 8 успешных проверок. См. [terminal-download-check.json](terminal-download-check.json).
