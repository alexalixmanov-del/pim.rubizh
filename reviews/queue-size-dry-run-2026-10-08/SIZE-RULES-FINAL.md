# Финальное правило размеров РУБІЖ — кандидат для проверки

Production не изменять до подтверждения dry-run владельцем. Модуль `lib/size-evidence.js` и офлайн-планировщик `lib/queue-dry-run.inc.js` подготовлены отдельно; они не подключены к startup действующей PIM. Исправления применяются только к изолированной копии аудита. Внешнему разработчику документ не отправлялся: получатель и канал не указаны.

Различать `EXACT_SIZE`, `SIZE_LIST`, `SIZE_RANGE`, `ONE_SIZE`, `NO_SIZE_REQUIRED`, `SIZE_CONFIRMATION_REQUIRED`. Отдельно хранить confidence `SAFE_AUTO / LIKELY / AMBIGUOUS`, доказательства, источник и привязку к supplier SKU.

Приоритет: отдельное size field/колонка поставщика → строка варианта → подтверждённое правило supplier SKU → variant name → title → attributes → description. Ручное подтверждение сохраняется. Слабый источник не перезаписывает сильный. Противоречия источников одинакового приоритета — exception. Отличия слабых источников сохраняются в диагностике.

Модельный диапазон не присваивается неизвестному SKU. По определённой системе он разворачивается только в ассортимент:

- `clothing_numeric`, 42–60, шаг 2: 42,44,46,48,50,52,54,56,58,60;
- `footwear_eu`, 40–46, шаг 1: 40,41,42,43,44,45,46;
- `letter_clothing`, S–XXL: S,M,L,XL,XXL; XS–3XL: XS,S,M,L,XL,XXL,XXXL;
- система/шаг неизвестны или границы противоречат системе: `AMBIGUOUS`, без угадывания.

Шаг берётся из системы соответствующего типа изделия / canonical category или уже подтверждённого supplier-specific правила. Математическое деление диапазона не определяет шаг. `46-48 / 46/48` в подтверждённом поле отдельного SKU одежды может означать один комбинированный размер. В общем описании это диапазон/перечень модели. `40-44` обуви не превращается в комбинированный размер одежды; отдельно учитываются стельки и явные двойные размеры обуви.

Поддерживаемые формы: дефис, длинное тире, `40...46`, числовые списки через запятую или `/`, буквенные списки/диапазоны, One Size, OS, універcальний; существующие составные форматы размер + рост / буква + long / буквенный размер шлема + обхват сохраняются без преобразования стандартов наугад.

Для каждого допустимого размера без отдельной строки/SKU/остатка:

```json
{"size":"50","supplier_sku":null,"stock":null,"stock_status":"UNKNOWN","availability":"SIZE_CONFIRMATION_REQUIRED","selectable_for_request":true,"checkout_allowed":false}
```

Это size option, а не складской вариант с новым RUB-SKU. Реальные SKU и variants не создаются из диапазона. `stock = 0` означает OUT_OF_STOCK. PREORDER разрешён только по явному подтверждению источника; срок не придумывается. Отсутствие размера не влияет на preorder. Просроченный остаток требует подтверждения наличия.

Безразмерный тип: `size_system = NONE`, `size_required = false`, размер не заполняется искусственным One Size. ONE_SIZE означает только явно указанный поставщиком универсальный размер.

Для модели передавать `size_system`, `allowed_sizes`, реальные `variants` и отдельные `size_options` с неизвестными остатками. Сайт только отображает нормализованные данные, не парсит диапазоны и не придумывает шаг. Неизвестные options доступны для заявки/уточнения, обычный checkout для них запрещён.

SAFE_AUTO применяется к изолированному кандидату. SAFE_AUTO ассортимент модели закрывает вопрос о трактовке размера, но не подтверждает конкретный SKU/остаток. Такие связи остаются в отдельных запросах поставщикам. LIKELY/AMBIGUOUS группировать по supplier + category + pattern; решение одной группы нельзя переносить на другие неоднозначные семейства.

Проверки: размеры из колонок, названий, variant label, supplier rule, attrs и description; приоритет, противоречия, комбинированные размеры; отсутствие fake SKU, stock и preorder; неизменность size mappings, taxonomy, aliases, supplier mappings и manual locks. Сравнивать не только количества, но и исходные SKU, supplier offers, цены, остатки, фотографии и привязки.
