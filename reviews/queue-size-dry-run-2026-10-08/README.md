# РУБІЖ: кандидат правил очереди и размеров, без установки на production

Это отдельные модули и результаты проверки. Они **не включены** в установочную сборку 10.9.2, её startup или команды выкладки. Здесь нет установщика. Production и текущие прайсы не изменялись.

`app/lib/size-evidence.js`: чистый модуль определения вида размерных данных, системы, приоритета источников и допустимых options без создания SKU/stock.

`app/lib/queue-dry-run.inc.js`: офлайн-планировщик четырёх очередей и строгие бизнес-правила. Функция изменений отказывается работать без явно изолированного audit context. Код намеренно отсутствует в `tools/build.cjs` действующей версии.

`SIZE-RULES-FINAL.md`: закреплённое правило и контракт для разработчика. `BLOCKED-TASKS.md`: конкретные отсутствующие компоненты магазина и данные поставщиков. `REPORT.md` / `summary.json`: результаты по исходным 671 вопросам и полному каталогу.

Повторный запуск в облачном рабочем каталоге с полной PIM 10.9.2 и приватными данными:

```sh
node --test app/tests/size-evidence.test.cjs app/tests/dry-run-business.test.cjs
node audit/queue-final-dry-run.cjs
```

Файлы в этом review повторяют пути исходного рабочего каталога: для независимой проверки их нужно наложить на исходники 10.9.2 из `releases/pim-10.9.2/rubizh-pim-10.9.2.zip`, установить зависимости существующей PIM и использовать `app/tests/isolated-harness.cjs`. Не выполнять наложение в webroot production.

Аудит требует приватных файлов `/workspace/private/pim-data/dry-run-baseline-10.9.2.json` и `dry-run-cases-10.9.2.json`, которые уже подготовлены в облачном workspace. Полная база, конфигурация, цены поставщиков, подробные списки артикулов и копия результата в Git не публикуются. SHA256 baseline приведён в `summary.json`. Детальная очередь, 27 групп LIKELY, supplier requests и интерактивный просмотр остаются в локальном `audit/final-dry-run/`.

По последнему указанию владельца наличие проверяется по историческим данным текущих прайсов **только в изолированной симуляции**. Реальные даты источников и настройка 36 часов не изменены. Перед запуском магазина должны быть актуализированы/подтверждены остатки; цены текущих прайсов сохранены для проверки.
