# Что конкретно отсутствует для магазина, checkout и автопрайсов

В наличии: исходники PIM из переданного архива, резервная копия каталога, существующие прайсы внутри данных, клиентский контракт API, офлайн-проверки и скрипт загрузки прайсов. Исходники витрины/сервера магазина, его структура проекта, схема БД, отдельная тестовая площадка и постоянные feed URLs поставщиков не предоставлены. Ниже названия файлов не выдумываются: нужен файл, который действительно выполняет указанную роль в вашем проекте.

| Задача | Конкретные недостающие файлы / ссылки / доступ |
|---|---|
| Сохранение модели → цвета → SKU | Файл маршрутов и controller/service действующего `POST /pim/sync`; ORM-модели/DDL и миграции таблиц products, variants, colors/галерей (или их реальные аналоги); обработка старых product IDs/redirects после объединения. Нужен файл дерева проекта и `composer.json` / `package.json`, чтобы определить реальные пути. |
| Переключение фотографий, размера и цены в карточке | Шаблон/component страницы товара; JS выбора цвета/SKU; serializer/controller публичного product API; CSS карточки; используемые DB-связи variant ↔ color ↔ photo; тестовая ссылка на модель с двумя цветами и несколькими размерами. |
| Показ разрешённых размеров с неизвестными остатками | Те же component/serializer плюс schema/migration для `size_system`, `allowed_sizes`, `size_options`; обработчик заявки на подтверждение размера. Важен контракт: options без SKU не становятся покупаемыми variants. |
| Проверка и скачивание фото | Controller/worker `POST /pim/photos`; исходник очереди скачивания, конфигурация media storage и путей, обработка MIME/404/таймаутов и связей фотографий; реальные результаты failed/pending/ok из `GET /pim/status`. Одних внешних URL в backup недостаточно для проверки доступности всех изображений. |
| PREORDER и заявки без известного размера/остатка | Файл формы и API заявки; service/store её сохранения и статусов менеджера; документированное подтверждение поставщиков по артикулам: разрешение изготовления, срок только если сообщён. Нулевой остаток не заменяет это подтверждение. |
| Проверка обычного заказа и комплекта | Файл маршрута фактического checkout endpoint (его URL ещё неизвестен); controller/order service; validation выбранных SKU/размеров/цветов/совместимости; сохранённый состав kit и quantity; схемы orders/order_lines/kits и транзакции. |
| Резервирование без перепродажи остатка | Stock/reservation service, DB-схема supplier stock pools и reservations, transaction/locking код, отмена заказа и expiry worker. Для внешнего склада нужен API/файл с реальным количеством по supplier SKU и правила подтверждения заказа поставщиком. |
| Цены, скидки, маржа и оплата | Серверные pricing/cart/promo services, сохранение полей pricing_policy/minimum_sale_price/kit_price; payment initiation и webhook/callback; sandbox-режим провайдера. Нужны условия предоставления оптовых уровней и фактические дополнительные расходы, если магазин учитывает их. Подмена цены клиентом должна блокироваться сервером. |
| Проверка совместимости PIM и серверного подтверждения | Controller `GET /pim/status`, response serializers для sync results/hide_ids/capabilities, серверные integration tests. Безопасный доступ к тестовому API через secret binding, не ключ в чате. |
| Проверка на хостинге и полный путь покупателя | Staging URL PIM + магазина; тестовый каталог/БД и тестовая учётная запись; sandbox оплаты; DocumentRoot/vhost/.htaccess или nginx config без секретов; реальная инструкция deploy/rollback и разрешённый terminal/SSH доступ через защищённое подключение. Известный путь PIM `/home/xk589064/rubizh.shop/pim/` не раскрывает путь storefront/server. Production сейчас заморожен владельцем. |
| Автопрайсы при закрытой PIM | Постоянная HTTPS ссылка XLS/XLSX/CSV/XML/API **для каждого**: М-ВІН, Tactical Belt, Armoline, UKR-TEC, Kiborg. У каждой — стабильный supplier SKU, цена/валюта/тип цены, количество или явно заданный статус наличия, updated_at/частота обновления; для размеров отдельная SKU-size строка, для предзаказа явный признак источника. Сейчас ни одной постоянной ссылки нет. Текущие прайсы сохранены. |
| Планировщик загрузки прайсов | Путь закрытого каталога для прайсов вне webroot; Python runtime/cron на хостинге; файл `feeds.json` с реальными URL и sid; расписание и правила доступа к закрытым фидам через secrets. Готовый локальный загрузчик: `app/server/fetch-supplier-feeds.py`; его размещение на хостинге не подтверждено. |
| Подхват обновлений магазином | Согласованный URL/контракт загрузки результата cron в PIM/server; service импорта со стабильными SKU, locks и историей; журнал успешной загрузки, endpoint статуса/ошибки. Постоянная ссылка без серверной интеграции не обеспечивает обновление магазина. |

Ни один из этих серверных компонентов нельзя считать реализованным на основании клиентского HTML. Цены текущих прайсов не требуют замены для проверки size/category logic. Для настоящего наличия необходимо обновление/подтверждение **остатков**, а не пересчёт розничных цен.

Текст поставщикам:

> Добрий день! Автоматизуємо оновлення каталогу РУБІЖ. Просимо надати постійне посилання на прайс XLSX/CSV/XML або API, яке оновлюється без зміни адреси. Потрібні окремі рядки для кожного артикулу/розміру/кольору: стабільний артикул, модель, розмір, колір, наша закупівельна ціна і валюта, рекомендована роздрібна ціна за наявності, кількість/статус наявності, дата оновлення, фото та опис. Якщо товар можна виготовити під замовлення, зазначте це окремим полем і вкажіть строк лише для підтверджених позицій. Загальний діапазон розмірів не замінює відповідність артикул → розмір і залишок. Якщо точних залишків немає, уточніть спосіб підтвердження конкретного розміру перед оформленням. Дякуємо!
