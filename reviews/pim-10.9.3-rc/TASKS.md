# Сохранённые задачи PIM и границы review RC

Inventory работа не заменяет исходные задачи. Production, сайт, deployment, sync, массовая публикация и архивирование запрещены до отдельного подтверждения. Сборка 10.9.3 RC предназначена для контрольной копии.

| Направление | Состояние после RC / что остаётся |
|---|---|
| Canonical categories | 143 категории в контрольной копии: 134 исходных объекта сохранены + 9 утверждённых IDs. Принятый category этап не пересмотрен; 124 исходных случая сверены с принятым отчётом. SAFE_AUTO отдельно от LIKELY/AMBIGUOUS, manual locks приоритетны. |
| Размеры | Runtime сохраняет EXACT_SIZE / SIZE_LIST / SIZE_RANGE / ONE_SIZE / NO_SIZE_REQUIRED / SIZE_CONFIRMATION_REQUIRED. allowed_sizes отдельно от реальных SKU, диапазоны не создают fake SKU или stock. Повторный импорт и dedicated size columns проверены. Итоговые числа в RC-REPORT. |
| MODEL → COLOR → SIZE/SKU | Существующие модели, все SKU, фото, prices, supplier bindings защищены контрольным сравнением. Similar name alone не объединяет товары. Переключение реальных фотографий по цвету на витрине ещё требует кода магазина. Shared supplier SKU не подтверждает автоматически каждый размер. |
| Inventory semantics | Реализованы STATUS для M-WIN, Киборг, Армолайн и подтверждённого Prom UKR-TEC. Tactical Belt — один supplier-level вопрос: подтвердить, означает ли «Наличие» количество единиц. Кандидат QUANTITY не активирован. FEED_PRESENCE требует отдельного подтверждения, никому из пяти не назначен. |
| Давность и last-valid observation | Реализовано: последний valid quantity/status действует до нового valid observation или manual correction. Freshness только warnings, imported_at не observation. Invalid/empty/older updates сохраняют прошлое состояние; manual locks приоритетны. |
| Заказ и оплата | Schema/export/SIMPLE/mock разделяют order_submission_allowed, payment_allowed, requires_order_confirmation. PREORDER / ORDER_ON_REQUEST / SIZE_CONFIRMATION_REQUIRED требуют менеджера перед оплатой. STATUS не требует численного количества. Это mock contract validation, реальный checkout ещё не изменён. |
| Защита данных, idempotency и rollback | Контрольный preview→apply и второй identical import, IndexedDB verification, schema всех exports; LOST_*, duplicates, PRODUCTION_WRITES=0. Cancel/stale preview/persist failure/verification failure проверяются tests. |
| Описания и бесплатный перевод | Предыдущие исправления генератора и локализации сохранены, соответствующие regression tests пройдены. Факты/комплектация поставщика не должны теряться; AI не придумывает характеристики. В этом RC автоматический refresh генератора во время replay выключен, чтобы не переписать контент. Новые реальные прайсы отдельно проверят full description mappings. |
| Фото и восстановление | Guards отсутствия usable photos сохранены. Review import не публикует, не скрывает и не архивирует товары. Reversible скрытие/архив и восстановление на реальном сайте нужно проверить после shop integration. Отсутствие описания само по себе не причина архивировать безопасно восстановимый товар. |
| Комплекты | Предыдущий подбор вариантов, количества компонентов, совместимость и расчёт цен сохранены и проверяются tests. Проверка наличия/размеров комплекта, reservation и менеджерское подтверждение в реальном заказе требуют shop backend и его данных. Нельзя резервировать fake quantities или model size options как SKU. |
| Маржа и цены | Согласованные 30% / 25% / 20%, guards скидок и минимальной цены сохранены. Этот import не мигрирует pricing policy. Исходные и calculated prices защищены сравнением до/после. |
| Исключения и упрощение UI | Category/size сгруппированы по rule/supplier/category/pattern. Inventory policy сгруппирована по поставщику, неизвестные values по pattern. Tactical Belt даёт один вопрос вместо 1512. Сохранены прежние кнопки/feedback fixes; финальную работу live UI пока не проверяли. |
| Реальный магазин: selector/gallery | Нужны исходник страницы товара и JS для selector цвета/размера/gallery; известный test/staging URL и способ проверить тестовый каталог. Точные repo paths владельцем ещё не указаны. |
| Реальный cart/checkout/payment | Нужны server cart/checkout handler, создание payment session, manager-confirmation endpoint, schema/DDL variants, orders/order_items, reservations. Без них mock не заменяет end-to-end заказ. Нужна тестовая среда магазина, production не подключать. |
| Реальный sync | Нужны server /pim/sync handler и status/capabilities endpoint, поддержка contract v3/order1/inventory1 и согласованные schema. /pim/sync текущей review PIM намеренно заблокирован. |
| REAL_SOURCE_COMPATIBILITY | Read-only checker и parser fixtures готовы. Для каждого из M-WIN, Tactical Belt, UKR-TEC, Киборг, Армолайн нужен один оригинальный XLS/XLSX/CSV/XML либо HTTPS URL с actual sheet/header/mapping. Backup содержит saved rows, не оригинальный workbook. Gate BLOCKED для всех пяти; production автопрайсы выключены. |
| Автопрайсы и hosting | После originals и подтверждённых supplier profiles отдельно проверить parser/import, затем test integration и release approval. Архив RC собран для review, на adm.tools/production не устанавливался. |

Текст запроса поставщикам: [SUPPLIER-REQUEST.md](../inventory-policy-final-dry-run-2026-10-08/SUPPLIER-REQUEST.md). Сообщения никому не отправлялись.
